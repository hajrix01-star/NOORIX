# خطة تحسين كتالوج الأصناف (الطلبات) — النسخة 2

**التاريخ:** 2026-05-29  
**النطاق:** تبويبة **إدارة الأصناف** داخل `/orders` فقط (`ItemsManageTab` وملحقاتها).  
**الحالة:** معتمدة للتنفيذ (MVP = المرحلتان 1 و 2).

---

## 1. المشكلة (ملخص تنفيذي)

كتالوج الأصناف **وظيفياً غني** (فئات، أقسام، متغيرات، استيراد، طباعة، فصل طلبات/مبيعات) لكن **تجربة الإدارة اليومية** ضعيفة:

- ازدواجية تبويب «أصناف الطلبات» / «أصناف المبيعات» بنفس الواجهة.
- نموذج إضافة ثابت يطغى على القائمة؛ التعديل داخل صف الجدول (صعب على الجوال).
- عدم اتساق مع بقية Noorix (`ScreenTabs`، فصل عرض/تحرير، شريط أدوات موحّد).
- **انحراف مواصفات:** `ORDERS_PLAN.md` يصف كتالوجاً بسيطاً (اسم، وحدة، فئة، سعر) بينما التنفيذ الحالي أعقد (متغيرات + أقسام + نوعين كتالوج).

**خارج النطاق (هذه الخطة):** تبويب الطلبات، تقارير الأصناف، طلبات الأقسام (Staff)، تغيير API المحاسبة، ترحيل `sectionId` (مرحلة لاحقة P3).

---

## 2. قرار معماري — الجداول و `SmartTable`

| الوضع الحالي | القرار v2 |
|--------------|-----------|
| `ItemsManageTab` مستثنى في `tables-audit.mdc` (تحرير ثقيل داخل `<table>`) | **نبقي الاستثناء للجداول داخل النماذج** (متغيرات داخل Sheet) |
| قائمة الكتالوج = `<table>` + تعديل inline في الصف | **نستبدل قائمة العرض بـ `SmartTable` للقراءة فقط** + **تحرير في `AdaptiveSheet`** |

**تحديث مطلوب بعد التنفيذ:** إضافة سطر في `tables-audit.mdc` يوضح أن استثناء `ItemsManageTab` يخص **جدول المتغيرات داخل النموذج** وليس قائمة الكتالوج الرئيسية.

**مرجع UX داخل نفس القسم:** `ItemsReportTab` + `OrdersTab` (قوائم بـ `SmartTable`).

## 3. ما نُبقي عليه (لا كسر)

- استيراد / تصدير Excel وقوالب الاستيراد (`OrdersImportModal`, `exportUtils`).
- ربط جماعي بالأقسام (`bulkSetSections`).
- إلغاء التفعيل (`deactivateOrderProductsBulk`) — الواجهة تعرض «إلغاء تفعيل» لا «حذف نهائي».
- فصل `productType`: `order` | `sale` (منطق API كما هو).
- قائمة Broasted الجاهزة (`BROASTED_PRESET_*`) — تبويب أصناف الطلبات فقط.
- طباعة الكتالوج + الورقة الأسبوعية (`ItemsCatalogPrintModal`, `ItemsCatalogWeeklyPrintModal`).
- تبويبات **الفئات** و **الأقسام** (تحسين ترتيب وعرض فقط في المرحلة 1، بدون إعادة كتابة كاملة).

## 4. MVP — المرحلة 1 (هيكلة وتنظيم)

**الهدف:** شاشة أوضح بدون تغيير سلوك API.

### 4.1 ترتيب التبويبات الفرعية

1. **الأقسام**  
2. **الفئات**  
3. **الكتالوج** (بدل تبويبين منفصلين)

### 4.2 تبويب الكتالوج

- `ScreenTabs` أو `variant="segmented"` داخل الكرت: **طلبات | مبيعات** (`productTypeFilter`).
- شريط أدوات واحد:
  - بحث
  - فلتر قسم (`select`)
  - فلتر فئة (`select`)
  - زر مسح الفلاتر
  - `KebabMenu`: قالب استيراد، استيراد، تصدير، طباعة كتالوج، طباعة أسبوعية، (preset لـ order فقط)
- **إزالة** تكرار أزرار الطباعة بين كرت الإضافة وشريط الفلاتر.
- نقل «+ إضافة صنف» إلى زر في شريط الأدوات (يفتح Sheet في المرحلة 2؛ مؤقتاً يمكن الإبقاء على كرت مضغوط قابل للطي).

### 4.3 توجيه قصير

- شريط معلومات أعلى الكتالوج (مرة واحدة / قابل للإغلاق):  
  **أصناف الطلبات** = مشتريات وطلبات أقسام · **أصناف المبيعات** = تقارير مبيعات الموظفين فقط.

### معايير قبول — المرحلة 1

| # | المعيار |
|---|---------|
| 1.1 | تبويبان فرعيان للمنتجات (`products` / `sales-products`) أُزيلا واستُبدلا بمبدّل واحد |
| 1.2 | ترتيب التبويبات: أقسام → فئات → كتالوج |
| 1.3 | أزرار الطباعة/التصدير تظهر مرة واحدة في شريط الأدوات (أو KebabMenu) |
| 1.4 | لا تغيير في payload الـ API للإنشاء/التحديث |
| 1.5 | معاينة يدوية: 1280px / 768px / 375px — لا فيض أفقي للصفحة (التمرير داخل الجدول فقط) |

## 5. MVP — المرحلة 2 (عرض احترافي + تحرير في Sheet)

**الهدف:** فصل العرض عن التحرير؛ تحسين الجوال.

### 5.1 قائمة الكتالوج

- `SmartTable` أعمدة مقترحة:
  - تحديد (checkbox)
  - اسم عربي / إنجليزي (truncate + `title`)
  - فئة
  - أقسام (Badges)
  - آخر سعر / ملخص متغيرات (`fmt`)
  - إجراءات: `KebabMenu` (تعديل، إلغاء تفعيل)
- `renderMobileCard`: اسم، فئة، أقسام، سعر.
- تحديد متعدد → شريط عائم: ربط أقسام، إلغاء تفعيل (كما اليوم).

### 5.2 إضافة / تعديل صنف — `AdaptiveSheet`

**تبويب أساسي (افتراضي):**

- اسم عربي*، إنجليزي، فئة، أقسام (checkbox chips)
- **وضع سعر بسيط:** حقل «آخر سعر» واحد (`lastPrice`) عندما لا توجد متغيرات فعّالة

**تبويب متقدم (اختياري):**

- جدول متغيرات (حجم، تعبئة، وحدة، سعر) — `<table>` مسموح داخل Sheet
- أزرار + حجم / + تعبئة كما اليوم

**قاعدة:** إن وُجدت متغيرات صالحة واحدة على الأقل → يُخفى `lastPrice` البسيط ويُعتمد على المتغيرات (سلوك API الحالي).

### 5.3 تقليل التعقيد الظاهر

- افتراضي: **صنف بسيط** (بدون فتح تبويب المتغيرات).
- رابط «إضافة أحجام/تعبئات متعددة» يفتح التبويب المتقدم.

### 5.4 فصل الملفات (صيانة)

```
src/modules/Orders/
├── components/catalog/
│   ├── CatalogToolbar.jsx
│   ├── CatalogProductTable.jsx      # SmartTable
│   ├── CatalogProductFormSheet.jsx  # AdaptiveSheet
│   └── CatalogTypeSegment.jsx       # order | sale
├── hooks/
│   ├── useOrderCatalogProducts.js
│   └── useOrderCatalogFilters.js
```

- تقليص `useItemsManageTab` إلى تنسيق التبويبات + تمرير `companyId` (هدف: &lt; 250 سطر في الـ hook الرئيسي بعد المرحلة 2).

### معايير قبول — المرحلة 2

| # | المعيام |
|---|---------|
| 2.1 | لا تعديل inline داخل صف `SmartTable` |
| 2.2 | إضافة صنف بسيط (اسم + فئة + قسم + سعر) في **≤ 4 نقرات** على الجوال (من فتح الكتالوج حتى حفظ) |
| 2.3 | تعديل سعر صنف موجود في **≤ 3 نقرات** (قائمة → تعديل → حفظ) |
| 2.4 | `renderMobileCard` يعمل لقائمة الأصناف |
| 2.5 | استيراد Excel وربط الأقسام الجماعي يعملان دون تغيير سلوك |
| 2.6 | `npm run build` ينجح؛ لا أخطاء lint في الملفات الملموسة |
